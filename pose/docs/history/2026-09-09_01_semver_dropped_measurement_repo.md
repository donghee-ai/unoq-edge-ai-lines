# 2026-09-09 — semver 로드맵 폐기 + v0.1.0 tag 제거

> [`2026-06-29_05_semver_v0_1_0_baseline.md`](2026-06-29_05_semver_v0_1_0_baseline.md)의
> 후속. 그 문서는 그 시점의 기록이므로 고치지 않는다 — 뒤집힌 사실은 여기에 적는다.

## 시점

2026-09-09 (카메라 테스트 프레임 히스토리 제거 작업 중, tag 정리하다 결정)

## 사건

06-29에 채택한 **semver 로드맵(v0.1.0 → v0.2.0 → ... → v1.0.0)을 폐기**하고
**`v0.1.0` tag를 로컬·원격에서 삭제**했다. 이 리포에는 이제 tag가 없다.

## 결정 근거

### 1. 이미 3개월째 안 쓰이고 있었다

06-29 로드맵의 다음 단계들은 **실제로 다 일어났는데 버전은 안 올라갔다.**

| 계획 | 실제 |
|---|---|
| v0.2.0 = PTZ PoC 검증 | PTZ는 검증을 넘어 **실기 동작**까지 갔다 (별도 리포 `health_care_bot`) |
| v0.4.0 = 하우징 시제품 | 하우징은 v8.43까지 진행됐다 |
| v0.3.0 = ASR → KWS 교체 | KWS 라인은 신설됐다 |

tag를 붙일 시점이 세 번 지나갔는데 한 번도 안 붙였다. 계획이 아니라 **관성으로만
남아 있던 상태**였다.

### 2. 계획을 담고 있던 상설 문서도 이미 내려갔다

`docs/07_versioning.md`는 상설 문서 통합(42개 → 5개) 때
[`history/superseded/`](superseded/07_versioning.md)로 이동했다. 지금 살아있는 문서
어디에도 semver·버전 로드맵 언급이 없다.

### 3. 리포 성격과 안 맞는다

루트 README가 스스로 규정하는 대로 **"이건 측정 리포다. 제품을 만드는 곳이 아니라,
'NPU 없이 이 정도 나온다'를 실기에서 확인하고 근거를 남기는 것이 전부다."**

semver의 `MAJOR.MINOR.PATCH`는 **배포되는 산출물의 호환성**을 표현하는 규약이다.
이 리포가 내놓는 건 소프트웨어가 아니라 **측정값**이고, 측정값은 버전이 아니라
**날짜와 조건**으로 식별된다(`docs/02_measurements.md`가 이미 그렇게 하고 있다).

제품 라인은 별도 리포(`health_care_bot`)로 분리됐으므로, 릴리스 버전이 필요해지면
그쪽에서 매기는 것이 맞다.

## 작업

```bash
git push origin --delete v0.1.0
git tag -d v0.1.0
```

- 삭제 전 복구 정보를 로컬에 남겼다(태그 객체 `6f87ebd`, 가리킨 커밋 `bbdcc7e`,
  태거·메시지 원문). 리포 밖에 있으므로 필요하면 작성자에게 문의.
- **tag가 가리키던 커밋 `bbdcc7e`("v0.1.0: 작품 전체 README 추가")는 히스토리에
  그대로 있다.** 라벨만 없앤 것이지 내용을 지운 게 아니다.
- GitHub Release는 애초에 만들어진 적이 없어(`gh release view` → not found)
  고아가 된 릴리스도 없다.

## 영향

- 코드·모델·문서 **변경 없음**. ref는 `refs/heads/main` 하나만 남는다.
- 06-29 문서의 "포트폴리오에서 v1.0.0으로 자연스럽게 승격" 시나리오는 **폐기**.
  포트폴리오 표기는 tag가 아니라 README의 실측 표로 한다 — 이 리포에서는 그쪽이
  실제로 보여줄 것이기도 하다.
- 앞으로 이 리포에 tag를 붙이지 않는다. 진척 추적은 지금까지처럼 각 라인
  `docs/history/`가 맡는다(06-29 문서가 이미 "라인별 진척은 history가 잘 처리,
  git tag는 작품 전체 release에만"이라고 적었는데, 그 "작품 전체 release"가
  이 리포에서 사라진 것이다).
